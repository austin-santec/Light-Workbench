Light Workbench

Current SQL Server insertion-loss testing workflow

Scope: This guide covers the normal hardware IL run using an ILM/OP815 and a supported Santec OSX-100 or OSX-150. The Red Light Test, standalone Live IL Reading, and Power Measurement Diagnostics are separate non-run tools.
Data storage: New accepted run data is stored in SQL Server. Existing CSV/JSON runs can still be opened for legacy review, but they are not writable database runs and are not silently uploaded.

1. Understand the main screen

Header

  • Select SM (1310/1550) or MM (850/1300).
  • Review the connected hardware identities.
  • Connect all hardware or one device at a time.

Left column

  • Enter Hardware test setup information.
  • Choose the channel plan and run purpose.
  • Review the readings table and run/result status.

Right column

  • Shows current readings, controls, and Reference.
  • Shows analysis, replacements, and Run information.
  • The lower information area scrolls independently.

Hardware test setup can be collapsed, and the center splitter can be moved, to give the readings table more room without clearing entered values.

2. Select the wavelength mode and connect hardware

  1. Connect the equipment physically. Connect the ILM/OP815, the switch, USB cables, and the approved optical test arrangement. Close Santec Terminal or any other program holding the switch's VISA resource.
  2. Select SM or MM. Use the two radio buttons in the header. SM measures 1310/1550 nm; MM measures 850/1300 nm. The application trusts this operator selection and does not infer the mode from the ILM serial, firmware, or model.
  3. Connect the hardware. Click Connect Hardware... to connect everything needed for a normal run. Use its menu only when you intentionally need to connect or disconnect the measurement hardware or switch separately.
  4. Verify the status panel. Both required devices must show a connected/available state before Start Run can proceed. The panel shows model and serial information when the device supplies it.
  5. Use ILM Remote Mode when needed. The checkbox is checked when Light Workbench controls the ILM. Clear it to return control to the ILM front panel without disconnecting the USB/DLL session, then check it again before resuming automated measurements.
  6. Resolve connection problems first. Use the detailed popup and Help > Support Logs if a device reports Error. Tools that use only one instrument may still operate when the other instrument is unavailable.
Mode timing: Select the wavelength mode before calculating a reference. Changing mode selects that mode's session reference and is blocked during active hardware work.

4. Calculate and maintain the reference

Session behavior: A reference belongs to the connected measurement session and selected wavelength mode, not to whichever run is displayed. Loading a database run or legacy CSV does not replace it.
  1. Make the approved reference connection and allow it to settle.
  2. Confirm the intended SM or MM mode is selected and the measurement hardware is connected.
  3. Click Calculate Reference in the Reference panel. Wait for both wavelengths to complete.
  4. Confirm Reference status reports a calculated reference for the current mode and connected measurement hardware.
  5. Reconnect the switch path for the run. Do not recalculate a reference while a hardware run is active.
Reference safeguards: A calculated power below -40.0 dBm is treated as a dark/disconnected reference and is rejected. A confirmed measurement-hardware disconnect clears the session references and requires recalculation. Returning the connected ILM to local/front-panel mode does not clear the reference, but recalculate if the optical path or source behavior was changed locally. Automated measurement remains blocked until ILM Remote Mode is restored. Disconnecting only the optical switch does not clear references. Manual reference authorization is available only in Admin Mode through Apply Manual Reference.

5. Understand the quality limits

Normal operators do not edit limits. The application selects the saved model/mode profile; authorized administrators can change profiles through Edit > Admin Mode... and Edit > Admin Config.... New runs snapshot the active criteria so later profile changes do not rewrite historical results.

OSX-100Below 0.2 dBNoneAbove 0.8 dB

The shipped SM and MM profiles currently use the same numeric values but are stored independently. Too-good and optimization conditions require review but do not make a row red. A formal failure makes the row red. A negative IL reading indicates a reference or connection problem; it may remain visible temporarily for troubleshooting but cannot be written.

6. Choose the channel plan

ControlUse
Full configured passNormal production plan. It tests logical channels 1 through the front-panel count derived from the part number. A larger temporary switch configuration does not expand this required pass.
Single channelTests one selected logical channel.
Specific channels/rangesTests a comma-separated plan such as 1, 3, 7-10. Repeated entries are tested once.
Choose channel order manuallyOptional full-pass workflow for scattered hardware. Select each next channel manually. A repeated accepted channel creates another attempt while the newest accepted attempt becomes the current table value.

7. Start and perform the run

  1. Click Start Run. Preflight checks the channel plan, required setup fields, SQL Server readiness, both hardware connections, and the authorized reference before creating or moving anything.
  2. Confirm the prompt. The confirmation identifies the run purpose and warns that the switch will move.
  3. Move the cable. Follow the active channel/physical-port message in Current readings.
  4. Wait for both wavelengths. Live Write Mode is enabled by default. It continuously obtains complete two-wavelength readings and waits approximately 250 ms after each completed pair before starting the next pair. Instrument and DLL response time make the total cycle longer.
  5. Review the pending reading. The displayed pair is temporary. Continuous updates never save a reading automatically.
  6. Click Write IL. Click Write IL or use its displayed shortcut, normally +. The complete pair is committed atomically to SQL Server, the table updates, and the worker advances.
  7. Repeat. Move the cable as directed, review the complete pair, and write it until the selected plan is finished.
Manual reading option: Before starting a run, clear Tools > Live Write Mode if you want separate Read IL and Write IL steps. Read IL measures and displays both wavelengths; only Write IL commits and advances.
Atomic readings: Light Workbench never treats one wavelength as a completed channel. If measurement or database persistence fails, no partial pair becomes an accepted measurement. Follow the popup; do not assume a value was saved merely because it appeared on screen.

8. Optional extra physical-port testing

After a successful automatic full pass covers every required front-panel channel, Light Workbench asks whether to finish or test additional physical ports through the switch's engineering interface. This applies to both a new full pass and a continued full pass that completes its remaining front-panel channels.

  1. Choose Finish Run unless extra spare-port measurements are intentionally required.
  2. If you choose Test Extra Ports, the program begins at front-panel count + 1 and routes each candidate sequentially using the fixed engineering command. When continuing a run, previously accepted extra-port readings are skipped and testing resumes at the first missing candidate.
  3. If the route cannot be verified, proceed only after independently confirming it. Otherwise choose Retry, No More Physical Ports, or Stop Extra Testing.
  4. A candidate is provisional until a complete valid two-wavelength result is explicitly accepted with Write IL and Continue.
  5. Choose No More Physical Ports when the current candidate is not installed. Choose Stop Extra Testing to end without making a capacity claim.
Extra-port boundaries: Sending a route command or seeing a temporary reading does not prove that a physical port exists. Failed, dark, stopped, retried, or unaccepted candidates are not saved. Accepted extras can support replacement analysis, but they do not count toward front-panel completion and are never written directly as COC channel rows.

9. Correct the channel or retest

Change Channel...

Use this during an active normal run when the requested channel is not the one you need next.

  1. Click Change Channel....
  2. Enter the logical channel and confirm.
  3. Move the cable to the newly requested channel.
  4. Review and write the reading normally.

In an ordered full pass, choose whether to continue from the selected channel or resume the interrupted channel afterward. Change Channel is unavailable during the extra-port phase.

Retest selected

Use this after readings have been written:

  1. Select one or more completed rows.
  2. Click Retest selected.
  3. Move the cable when prompted, then review and Write IL.

The latest accepted attempt becomes the displayed value. Earlier accepted attempts remain in append-only database history. Use View Reading History... in Run information to review them.

11. Finish, stop, and review a run

  1. Allow the plan to finish or click Stop run. Successfully accepted readings remain in SQL Server. A stopped run is marked accordingly rather than presented as complete.
  2. Review the post-run optimization offer. A completed eligible full pass may ask whether you want optimization recommendations. Yes opens the existing replacement analysis; No simply dismisses it. This is not a COC prompt.
  3. Load a database run later. Enter the unit's Main board serial and Run number, then use Load Run. Database Reports provides broader read-only searches across assignments, runs, measurements/retests, and replacements.
  4. Review attempt history. Use View Reading History... to see the original accepted reading and every accepted retest for the loaded database run.
  5. Open legacy data when needed. Open Existing CSV and File > Open CSV Run... load older file-backed data for review and export. A legacy CSV is not converted into a writable database run.
  6. Clear the workspace between units when needed. File > Clear Workspace... unloads the displayed run and resets setup fields, readings, analysis, comparison, and table content. It does not delete saved SQL/CSV data, disconnect hardware, change wavelength mode, or invalidate the current session reference. Finish any active acquisition, reference calculation, or database write first.
  7. Copy values when needed. Copy Raw Data... copies accepted channel/wavelength values as tab-separated text. It ignores the current table filter and does not create or modify run data.

12. Replacement analysis and records

Analyze Replacements uses accepted front-panel readings and accepted extra-port readings to suggest improvements for OSX-150. The minimum worthwhile improvement is controlled in Edit > Admin Config for OSX-150 and each wavelength mode, and defaults to 0.2 dB. OSX-100 has no replacement-analysis threshold because it does not use extra channels. Recommendations are advisory. Light Workbench does not command the switch to change a permanent mapping and does not use CLOSe? to verify a replacement.

Routing confirmation: On approved firmware, CLOSe? reports the active logical channel. Light Workbench compares it with the requested logical channel before measuring. The physical port shown or saved for a normal/replacement reading comes from the recorded assignment map, not from CLOSe?.

After a physical reroute is completed through the approved external process, use Manage Port Replacements.... For database runs, select the logical channel; Light Workbench supplies the current effective port, assignment/run context, identity, and UTC timestamp. A selected recommendation also supplies its proposed port, category, improvement, and an editable default reason. For a manual change, choose the logical channel and proposed physical port.

You must provide or confirm the reason and operator, may enter optional details, and must explicitly confirm that the physical reroute was completed outside Light Workbench. Opening or canceling the window records nothing. SQL history is append-only: Replace Again and correction/reversal actions add a row instead of deleting history. Existing and recommended designated spares are reviewed before Save. The application then reloads the effective map and audit history from SQL Server.

Replacement boundary: Light Workbench records the operator's documentation. It does not command the switch to change its permanent mapping, does not use CLOSe? to verify a replacement, and does not infer that an analysis recommendation was completed.

13. Write a COC explicitly

  1. Click Write COC... or use File > Write COC.... Completing or stopping a run never starts COC creation automatically.
  2. Select one persisted base run and, when needed, one compatible supplemental/retest run. Run purpose does not by itself block COC eligibility.
  3. Review the derived front-panel count and validation summary. Required channels must be present, valid, non-negative, physically consistent, and below the COC failure boundary after four-decimal rounding.
  4. For a combined result, supplemental readings replace complete channel pairs and must agree with documented port replacements when the physical port changes.
  5. For a database run, choose the output folder. Light Workbench selects the model/mode/capacity template and creates a new timestamped workbook without changing the template.
Supported templates: OSX-100 supports SM and MM COCs. OSX-150 supports SM COCs. Capacity 1-45 uses the 45-channel template and 46-48 uses the 48-channel template. Extra physical ports are excluded from direct COC rows.

14. Support and troubleshooting

SituationOperator action
Hardware will not connectRead the complete connection popup, verify power/USB/VISA ownership, close Santec Terminal, and reconnect. Do not interpret every VISA code as proof of a physical disconnect.
Reference rejectedCheck the reference cable, seating, selected mode, and received power. A dark reading below -40.0 dBm cannot authorize a run.
Negative IL displayedCheck the active reference and current optical connection. The value cannot be written as valid data.
Database unavailableThe run or reading is not treated as successfully stored. Keep the application open, follow the popup, and contact support before repeating work.
COC blocked or failedUse the validation or technical details in the dialog. The local support log correlates explicit COC attempts for engineering review.
Engineering support neededUse Help > Support Logs to open the local logs folder, inspect logging status, copy its path, or export a support bundle.

Complete serials, part number, band, initials, station, run number, and purpose. 5. Confirm the derived front-panel channel count. 6. Calculate Reference for the selected mode and connected ILM. 7. Choose Full pass, Single channel, or Specific channels/ranges. 8. Click Start Run and approve switch movement. 9. Move the cable to the displayed channel/port. 10.
